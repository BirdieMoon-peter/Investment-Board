# 自选股闭环 MVP 设计文档

日期：2026-03-10
状态：approved-for-planning
来源：`investment_dashboard_plan.md`（产品总方案输入，不替代 workflow source of truth）

说明：本文档是进入实现计划前的跨模块设计产物，用于定义第一个产品闭环与模块推进顺序；实际执行仍以 `docs/02-module-registry.md`、对应模块文档和 `memory/progress.md` 为准。

## 1. 背景

`investment_dashboard_plan.md` 定义了一个面向个人投资者的 A 股智能投研与组合管理平台。该总方案覆盖前端、后端、数据层、AI、通知、复盘等多个独立子系统，范围过大，不适合作为单一实现目标直接开工。

因此，第一轮开发应先拆出一个最小可用闭环，并以该闭环作为后续模块推进的起点。

## 2. 本轮目标

本轮定义的第一个子项目为：**自选股闭环 MVP**。

首条用户路径为：

1. 用户搜索股票代码或名称
2. 用户将股票加入自选
3. 系统持久化该自选关系
4. 用户在自选列表中看到基础真实数据

本轮要求：

- 支持单用户、本地持久化、无登录
- 支持添加 / 删除自选
- 支持按股票代码或名称搜索
- 搜索支持代码和名称的精确匹配与前缀 / 局部匹配；MVP 不支持拼音、别名和复杂排序策略
- 默认排除不可交易或失效证券；如数据源缺失该状态字段，则至少保证结果可被后续自选流程校验
- 自选列表展示真实字段：代码、名称、行业、最新价、涨跌幅
- 所谓“真实数据”在 MVP 中指来自真实证券主数据源和真实行情快照源的结构化数据；允许采用延迟数据、手动刷新或定时同步，不要求实时推送
- 新闻 / 公告 / 事件流暂不接真实数据，可先留空或 mock

## 3. 非目标

本轮明确不做以下内容：

- 持仓管理
- 个股详情页
- AI 个股分析
- 推荐引擎
- 分组管理（观察池 / 核心池 / 备选池）
- 多用户与登录体系
- 实时推送与高频行情
- 完整 K 线、分钟线、技术指标体系
- 新闻 / 公告抓取与结构化处理链路

这些能力可以在后续模块中逐步接入，但不应阻塞自选股闭环 MVP 的落地。

## 4. 推荐方案

采用 **“数据层先行，再接后端，再接前端”** 的推进方式。

### 4.1 方案说明

1. 先定义证券主数据、自选关系和最小行情快照模型
2. 再实现搜索、自选增删、自选列表查询接口
3. 最后接入前端列表页与搜索交互

### 4.2 采用该方案的原因

- 符合“先打数据底座”的明确偏好
- 与当前项目 workflow 的模块边界一致
- 有利于后续扩展个股详情、持仓、推荐等能力
- 能控制第一阶段范围，避免一次性建成完整投资系统

## 5. 模块推进顺序

建议按以下顺序推进：

1. `data-layer`
2. `backend`
3. `frontend`
4. `scripts`（仅在需要初始化或同步数据时补充）

### 5.1 data-layer 职责

- 定义证券主数据模型
- 定义自选股关系模型
- 定义最小行情快照模型
- 为搜索与列表查询提供稳定的数据边界

### 5.2 backend 职责

- 提供搜索证券接口
- 提供添加自选接口
- 提供删除自选接口
- 提供获取自选列表接口
- 组合并返回前端需要的最小视图数据

### 5.3 frontend 职责

- 提供股票搜索输入与结果展示
- 提供添加自选交互
- 提供删除自选交互
- 提供自选列表的展示与空状态 / 错误状态

### 5.4 scripts 职责

- 如需要，提供证券主数据导入或更新脚本
- 如需要，提供最小行情快照同步脚本

## 6. 目标架构

第一阶段采用单体 Web 应用结构：

```text
Frontend (watchlist search + list)
    ↓
Backend API
    ├─ search securities
    ├─ add/remove watchlist item
    └─ fetch watchlist view
    ↓
Data Layer
    ├─ securities
    ├─ watchlist_items
    └─ quote_snapshots
```

### 6.1 架构原则

- 只为当前 MVP 设计最小必要实体与接口
- 数据层实体可扩展，但不预先实现未来需求
- 行情能力仅满足列表展示最新价与涨跌幅
- 事件流位置允许预留，但不阻塞主链路

## 7. 核心数据模型

本轮只定义 3 个核心实体。

### 7.1 `securities`

证券主数据表，用于支撑搜索和显示基础信息。

建议最小字段：

- `id`
- `code`
- `name`
- `market`
- `industry`（允许为空）
- `status`
- `created_at`
- `updated_at`

约束：

- `code` 在 `market` 维度内唯一，推荐建立 `(market, code)` 唯一约束

用途：

- 支撑按代码 / 名称搜索
- 作为自选关系与行情快照的基础实体
- 为后续扩展概念、板块、市值等属性提供承载点

### 7.2 `watchlist_items`

自选关系表，用于保存当前单用户的自选股票。

建议最小字段：

- `id`
- `security_id`
- `created_at`

约束：

- `security_id` 唯一，防止重复添加同一股票
- 删除自选时仅删除自选关系，不删除证券主数据

说明：

- 第一阶段不引入 `users` 表
- 整个系统默认只有一个本地用户上下文

### 7.3 `quote_snapshots`

最小行情快照表，用于列表展示最新价与涨跌幅。

建议最小字段：

- `id`
- `security_id`
- `last_price`
- `change_amount`
- `change_percent`
- `snapshot_time`
- `created_at`

说明：

- 当前只要求“可展示的最新快照”
- 自选列表取最新行情时，以 `snapshot_time` 最大的记录作为该证券最新快照，推荐为 `(security_id, snapshot_time)` 建索引
- 不要求在本轮实现完整日线、分钟线和技术指标模型

## 8. 关系与查询视图

推荐使用 `security_id` 作为关系键，不直接只靠 `code` 建立关联。

关系如下：

- `securities` 1 -> N `quote_snapshots`
- `securities` 1 -> 0/1 `watchlist_items`（在单用户前提下）

自选列表查询逻辑：

1. 从 `watchlist_items` 获取全部自选证券
2. 关联 `securities` 拿到代码、名称、行业等主数据
3. 取每只证券最新一条 `quote_snapshots`
4. 组装成前端列表所需视图

列表输出视图至少包含：

- `code`
- `name`
- `industry`
- `last_price`
- `change_percent`
- `snapshot_time`

## 9. 数据流与同步策略

### 9.1 搜索流

1. 数据层准备好证券主数据
2. 后端按代码 / 名称查询 `securities`
3. 前端展示搜索结果
4. 用户选择结果并发起添加自选

### 9.2 添加自选流

1. 前端提交目标证券标识
2. 后端校验证券是否存在
3. 若未存在自选关系，则写入 `watchlist_items`
4. 返回最新自选列表或新增项结果

### 9.3 列表展示流

1. 前端请求自选列表
2. 后端读取自选关系、证券主数据和最新行情快照
3. 后端返回聚合后的列表视图
4. 前端按表格或列表渲染结果

### 9.4 删除自选流

1. 前端提交要删除的自选项
2. 后端删除 `watchlist_items` 对应记录
3. 保留 `securities` 与 `quote_snapshots`
4. 返回更新后的列表或删除成功结果

### 9.5 行情同步策略

第一阶段行情只需满足列表展示，不追求高频实时。

建议策略：

- 证券主数据：通过初始化脚本导入，后续按需增量更新
- 行情快照：通过定时同步或手动刷新方式写入最新价和涨跌幅
- 若某只证券暂无行情快照，列表允许显示空值或“待同步”状态
- `scripts` 模块默认不进入本轮主实现范围；仅当证券主数据初始化或行情快照同步必须通过脚本完成时，才将最小导入 / 同步脚本纳入 setup 范围

## 10. 接口边界

第一阶段后端只需要以下最小接口集合：

### 10.1 搜索证券

- 用途：按代码或名称搜索可加入自选的证券
- 输入：查询关键字
- 输出：证券基础信息列表
- MVP 搜索结果建议限制返回前 20 条
- 结果优先按代码精确匹配、名称精确匹配、代码前缀匹配、名称局部匹配的顺序返回

### 10.2 添加自选

- 用途：将证券加入当前单用户自选列表
- 输入：证券标识
- 输出：成功结果或重复添加提示

### 10.3 删除自选

- 用途：从当前自选列表移除证券
- 输入：`security_id`
- 输出：成功结果

### 10.4 获取自选列表

- 用途：获取自选列表展示视图
- 输出：代码、名称、行业、最新价、涨跌幅、更新时间等字段

说明：

- 第一阶段不引入复杂筛选、排序、分页规则，除非实现成本极低
- 第一阶段不提供事件流真实接口，前端可先不显示或以 mock 占位

## 11. 错误处理

系统需显式处理以下最小错误场景：

### 11.1 搜索无结果

- 后端返回空列表
- 前端显示明确空结果状态

### 11.2 添加重复自选

- 后端返回幂等结果或明确提示“已在自选中”
- 前端不出现重复行

### 11.3 添加不存在证券

- 后端拒绝写入并返回明确错误
- 前端展示可理解提示

### 11.4 行情缺失

- 自选列表仍可显示证券基础信息
- 行情字段可为空或显示“待同步”
- 不因单个证券行情缺失导致整个列表失败

### 11.5 数据同步失败

- 不影响已保存的自选关系读取
- 需保留最小错误记录能力，便于后续定位问题

## 12. 验证与测试策略

验证目标是确认 MVP 主链路可用，而不是提前覆盖全部未来场景。

### 12.1 data-layer 验证

- 能创建并读取 `securities`
- 能创建并删除 `watchlist_items`
- 能写入并读取 `quote_snapshots`
- 唯一约束可阻止重复自选
- 关系查询能返回正确聚合结果

### 12.2 backend 验证

- 搜索接口能按代码 / 名称返回结果
- 添加自选接口能正确写入并处理重复添加
- 删除自选接口能正确移除记录
- 自选列表接口能返回聚合后的视图字段
- 关键失败路径返回可识别的错误结果

### 12.3 frontend 验证

- 搜索输入与结果展示正常
- 添加自选后列表正确刷新
- 删除自选后列表正确刷新
- 空列表、空搜索结果、行情缺失状态有明确展示

## 13. 里程碑建议

### 里程碑 1：数据底座

- 建立 3 个核心实体
- 建立最小数据访问边界
- 打通证券主数据初始化方式

### 里程碑 2：最小 API

- 搜索证券
- 添加自选
- 删除自选
- 获取自选列表

### 里程碑 3：最小 UI

- 搜索框
- 搜索结果选择
- 自选列表展示
- 删除自选

## 14. 决策摘要

已确认的设计决策：

- 第一子项目是“自选股闭环 MVP”
- 第一条主路径是“添加自选并查看列表”
- 真实数据范围限于基础信息、最新价、涨跌幅
- 单用户、本地持久化、无登录
- MVP 功能只包含添加 / 删除自选、证券搜索、列表字段展示
- 推进方式选择“数据底座优先”
- 数据模型先收敛为 `securities`、`watchlist_items`、`quote_snapshots`
- 关系键优先使用 `security_id`
