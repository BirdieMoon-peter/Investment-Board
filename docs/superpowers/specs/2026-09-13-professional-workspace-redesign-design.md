# Investment Board 专业工作台重设计

日期：2026-09-13  
状态：现状审查与方案自检完成，等待用户确认后进入实现。  
范围：frontend 模块。现有 API、数据库、AI 配置协议与外部服务认证保持独立。

## 设计判断

面向个人投资研究的日常工作台。用稳定的位置、可比较的数字和明确的操作层级，缩短“观察市场、筛选自选、研究标的、处理持仓与 AI”的路径。

- 模式：视觉重设计，同时按用户要求调整任务流。保留全部现有内容与功能入口、项目名称、页面 URL、表单字段顺序与已有双语能力。
- DESIGN_VARIANCE: 3。规则网格和可预测的位置优先于表现性排版。
- MOTION_INTENSITY: 2。仅必要的 hover、按下和焦点反馈，无自动轮播、滚动劫持或装饰动画。
- VISUAL_DENSITY: 8。数字密集但分组清晰，使用区域与分隔线组织信息，减少嵌套卡片。
- 采用官方 Fluent UI React v9 作为唯一组件设计系统；表格排序筛选逻辑使用 TanStack Table，实际图表继续使用项目已有的 Lightweight Charts。
- `design-taste-frontend` 第13节明确排除仪表盘。此项目应用其重设计审查、主题、对比度、字体和一致性要求；营销页 hero、摄影、bento、品牌墙及滚动叙事规则不适用。

## 视觉系统

- 全局提供浅色、深色、跟随系统三个选项，默认跟随系统。页面、抽屉、菜单、图表使用同一主题，已有语言和密度偏好继续保留。
- 采用 Fluent 的官方浅/深主题和语义色；只定制品牌蓝、字体和必要的布局尺寸，不重新仿造全部控件样式。
- 蓝色表达操作和选中；红绿仅表示行情语义。保持当前绿涨红跌约定，数字显示正负号，避免仅靠颜色传达意义。
- 数字采用等宽字体和 tabular-nums，价格、涨幅和成交量右对齐；缺失值使用“暂无”或对应英文文案。保留原始精度，缩写成交量时提供原值。
- 桌面顶部栏64px，内容最大宽度1400px；4px间距体系，主要间距8/12/16/24px。正文14-16px，标题20-24px，主要价格28-32px。
- 图标统一使用 Phosphor regular 一套图标，不绘制自定义路径。禁止新增营销插图和无依据的业绩数字。
- 对比度按 WCAG AA 检查正文、按钮、表单辅助文字与焦点；正文以 AAA 为目标。尊重 reduced-motion。
- 系统层级统一为：内容0、粘性栏10、抽屉/菜单使用 Fluent 自身层级。避免随意叠加高 z-index。

## 首页布局与行为

```text
┌ 投资看板                       主题  立即同步  打开设置 ┐
├ 大盘指数：紧凑横向摘要，含涨幅和真实来源时间             ┤
├ 自选概览：数量、已同步状态、刷新与同步反馈               ┤
├──────────────────────────────────┬────────────────────┤
│ 自选股                           │ 焦点标的           │
│ 本地筛选  市场筛选  搜索与添加     │ 最新行情 / 详情入口│
│ 名称/代码  最新价  涨跌幅  AI  ⋯   ├────────────────────┤
│ 可排序的数据行                   │ 宏观摘要           │
│                                  │ 来源与发布时间     │
└──────────────────────────────────┴────────────────────┘
```

- 原大标题区域缩成紧凑看板摘要。既有 `showHero` 偏好映射为是否展示该摘要，不删除用户偏好；`showSpotlight`、大盘、宏观、AI标签开关继续有效。
- 桌面主区约72%、辅助栏约28%。在1440×900和默认设置下，自选表头和至少5条演示数据行应出现在首屏；加载或外部数据异常也不能把自选推到页面末尾。
- “筛选自选”只过滤已加载列表；“搜索与添加”单独打开搜索对话框，沿用后端查询与自定义六位代码添加流程，避免混淆本地筛选和全市场搜索。
- 自选支持代码/名称关键词、SH/SZ市场筛选，以及名称、最新价、涨幅排序。数值按数值排序，空值固定置后。默认保持已有顺序，不把“全部数据”和“筛选结果”数量混为一谈。
- 详情入口使用名称按钮，辅助菜单提供移除。移除先显示包含标的名称的确认；取消不发出请求。操作按钮不会同时触发详情导航。
- 进入详情再返回时，保留本地筛选、排序和列表滚动位置，并恢复到对应标的入口的焦点。
- 搜索通过显式提交触发，不新增自动外部请求；重复添加有清晰反馈，不重复插入记录。搜索请求被新查询或关闭淘汰时，不允许旧结果覆盖当前状态。
- 大盘和宏观加载/失败各自反馈，不阻塞自选。同步按钮对应现有全看板同步；自动刷新/同步的现有时间间隔和调度逻辑保持。

## 标的详情布局与行为

顶部保留返回自选、标的身份、最新价格/涨幅、来源时间和同步操作。使用三个相关内容分组：

1. **行情与基本面**：K线与成交量占主要宽度，旁侧提供行情摘要；财务、公司简介在下方分组，原始价格明细按需展开，保留分页。
2. **资讯公告**：公告与新闻分栏，保留真实标题、来源、时间与原链接；窄屏顺序展示。
3. **持仓与 AI**：左侧持仓概况/编辑，右侧分析结果与历史；库存缓存和新生成操作仍明确分开，保留所有原有股票/持仓作用域能力。

- 默认进入“行情与基本面”。用官方 TabList 实现，移动端空间不足时改用同值选择控件；键盘焦点和选中状态正确。
- 切换分组不清空持仓草稿、已选分析或历史，也不触发新的模型请求。
- 仍由原 StockDetailPage 维护数据加载、持仓草稿和分析选择状态。拆出的展示组件不复制业务请求。
- 图表主题变化只更新样式，不重建数据或重置用户可见时间范围。容器隐藏/展示、尺寸变化和卸载需正确处理，不出现空白画布和泄漏。
- 获取到部分信息时展示可用部分，失败反馈落在所属区域，保留现有初始历史请求竞争保护。

## 设置抽屉与 AI 配置

- 现有“打开设置”入口保留，并在详情页同样可访问。桌面使用右侧宽抽屉，移动端使用全宽抽屉，关闭后恢复原入口焦点。
- 抽屉分为“界面与刷新”和“AI 服务配置”。既有控件含义、顺序和标签保持，新主题选项追加到一般显示偏好。
- 界面偏好仍即时生效；AI仍需要显式保存。切换设置分组不丢弃未保存AI草稿，关闭时若有草稿则提示“继续编辑/放弃修改”。任何关闭途径包括 Escape 都适用。
- 未保存密钥只在本次打开期间的组件内存中保留，确认放弃或完成保存后清除。AI保存、草稿测试、清除密钥、恢复环境配置以及后端409检查均保持现有契约。
- 保存/测试/恢复进行时禁用重复操作与抽屉关闭，操作完成或失败后恢复；刷新或卸载仍按现有取消/过期响应规则处理。
- AI页第一次打开时才加载配置，首页启动和切换主题不会触发配置测试或模型请求。

拟拆分：AppThemeProvider、WorkspaceHeader、MarketStrip、WatchlistWorkspace、SecuritySearchDialog、SettingsDrawer、DetailWorkspaceTabs；在既有 API clients 上复用请求逻辑。保留 React/Vite 项目结构，不迁移到 Next.js，也不混入第二套视觉组件库。

实现时先检查 package.json，并使用官方包：

```bash
npm install --prefix frontend @fluentui/react-components @tanstack/react-table @phosphor-icons/react @fontsource/ibm-plex-sans @fontsource/ibm-plex-mono
```

安装前核对当前 React19 兼容性和包的官方说明；使用锁文件记录实际版本。字体使用本地打包资源和 font-display: swap，不请求第三方字体CDN。

## 移动端与可访问性

- 在320/390px保留名称/代码、价格、涨幅和操作；次要自选字段可展开查看，不以横向拖动整个页面作为默认操作。
- 768px以下主区单列，顺序为市场摘要、自选、焦点、宏观；顶部动作收敛为有清晰标签的紧凑控件。
- 原始宽表格仅在容器内滚动，图表必须适应实际宽度。桌面按钮文字不换行。
- 对话框和抽屉正确捕获/恢复焦点；危险操作有具体对象；表格排序具有 aria-sort；所有输入有独立标签，图标操作有可访问名称。
- 加载态使用与最终数据块对应的骨架。空列表、筛选无结果、搜索无结果、外部服务失败、离线缓存各自有正确后续操作。
